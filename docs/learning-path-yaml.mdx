## Explanation

The learning path is intentionally not tool-first.

Each section starts with the security problem, then explains where it fails in real pipelines, then introduces tools only as controls.

## How To Use This YAML

Use `section` as the sidebar category.

Use `purpose` as the introduction paragraph for each page.

Use `key_topics` as article subsections.

Use `outputs` as the practical assets every serious blog should include, like workflow YAML, diagrams, PR comment examples, and security gate policies.

## Simple Publishing Rule

Every article should answer four questions:

```yaml
article_standard:
  question_1: "What problem are we solving?"
  question_2: "Why does it matter in a real CI/CD pipeline?"
  question_3: "Where should this control run?"
  question_4: "What YAML, command, diagram, or screenshot helps the developer apply it?"
```

This keeps the series practical and professional.
