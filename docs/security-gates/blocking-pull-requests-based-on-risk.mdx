# Blocking Pull Requests Based on Risk

Security quality gates decide when a pull request is allowed to merge.

The gate should not block every issue. It should block agreed risk.

## Example Policy

```yaml
quality_gate:
  block:
    sast:
      severity: [critical, high]
    secrets:
      severity: [critical, high, medium]
    dependencies:
      severity: [critical]
      exploit_available: true
    iac:
      severity: [critical, high]
  allow:
    risk_acceptance_required: true
    expiry_days: 30
```

## Fail Open vs Fail Close

| Mode | Meaning | Use Carefully |
| --- | --- | --- |
| Fail open | Pipeline continues when scanner fails | Good during rollout |
| Fail close | Pipeline fails when scanner fails | Good for mature required controls |

For secrets, fail close is usually correct.

For a new SAST rollout, fail open with reporting may be better until the rules are tuned.
