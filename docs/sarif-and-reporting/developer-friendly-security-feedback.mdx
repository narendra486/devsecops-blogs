# Creating Developer-Friendly Security Feedback

Security findings should appear where developers already work.

For GitHub teams, that usually means:

- check runs,
- code scanning alerts,
- inline annotations,
- pull request comments,
- and required status checks.

## SARIF Upload Example

```yaml
- name: Upload SARIF
  uses: github/codeql-action/upload-sarif@v3
  with:
    sarif_file: results.sarif
```

## PR Commenting Tools

Reviewdog can convert scanner output into pull request comments.

```yaml
- name: Run reviewdog
  uses: reviewdog/action-setup@v1

- name: Comment findings
  run: |
    scanner-command --format checkstyle > results.xml
    reviewdog -f=checkstyle -name="security-scan" -reporter=github-pr-review < results.xml
```

Good reporting reduces repeated AppSec follow-up.
